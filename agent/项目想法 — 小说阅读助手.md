# 项目想法：小说阅读助手（RAG + AI）

## 结论先行

**使用 RAG/LLM 分析小说全文内容，在当前技术条件下不现实。** 不是技术能力不够，是技术边界使然。

经过完整技术推演，最终收敛到务实方案：**不对小说原文做深度理解，用已有的书评/解析/百科做知识库**。

## 用户能力矩阵（学完的技能）

- Tool Calling（@tool → bind_tools → 执行 → 总结）
- LCEL（管道串联、RunnableParallel、RunnableBranch）
- Memory（InMemory + Redis 持久化）
- RAG（ChromaDB + Embedding + 检索）
- MCP（STDIO + SSE 双模式）
- 向量库操作（写入/检索/删除/持久化）
- Pydantic 数据建模

## 推演过程：为什么完整方案走不通

### 尝试 1：单一 RAG → 不行

小说答案是**跨章节因果链**，不是单个 chunk 能回答的。Hybrid Search + Reranker 能精准搜到原文片段，但碎片乱序，LLM 需要自己拼因果链条。

### 尝试 2：Multi-RAG 分库检索 → 部分改善

```
因果库（小块 200 字）+ 对话库（大块 600 字）+ 摘要库（不切）
→ LCEL RunnableParallel 并行 → 提高召回
```

价值：多维度找到更多相关碎片。局限：LLM 拿到的仍然是乱序碎片。

### 尝试 3：时间轴排序 → 对特定文本可行，对多数文学无效

```python
# 每个 chunk 打章节号 metadata → 检索后按时间排序
metadata = {"chapter": 3, "story_time": "2018年春", "event": "张三被冤"}
```

| 文本类型 | 能提取时间轴吗 | 原因 |
|----------|:--:|------|
| 侦探/推理小说 | ✅ | 显性因果链 + 时间标记 |
| 网文/玄幻 | ⚠️ 部分 | 有事件但时间标记模糊 |
| 散文/随笔 | ❌ | 没有因果链，只有意象和情绪 |
| 意识流/后现代 | ❌ | 刻意消解时间 |
| 诗歌 | ❌ | 语言碎片，不构成叙事 |

**对 80% 的文学作品，强行做时间轴 = 用错误的方法套错误的文本。**

倒叙/插叙/多线叙事等写法，章节号不等于时间戳。非显性时间过渡词（散文常见）根本无法定位事件顺序。

### 技术边界：RAG 对小说的真实能力

```
能做：
  ✓ 搜原文片段（"张三在哪一章死的？"）
  ✓ 查书评/解析/百科（已有的结构化知识）
  ✓ 找特定对话或描写（关键词匹配 + 向量）

做不了：
  ✗ 理解情节因果（跨章节推理）
  ✗ 分析人物弧光（需要全局视角）
  ✗ 捕捉主题和意象（需要人的感受力）
```

## 务实方案：书评+百科 RAG 助手

不对小说原文做深度理解，用已有的外部知识做索引：

```
数据源：
├── 豆瓣书评（短评 + 长评）
├── 知乎/公众号解析文章
├── 百度百科/维基百科词条
├── 作者访谈
└── 小说原文（仅做关键词检索，不做因果推理）

用户问"这本小说讲什么？"  → RAG 查书评摘要
用户问"主角什么性格？"    → RAG 查人物分析
用户问"结尾有什么争议？"  → RAG 查讨论帖
用户问"第几章有那段对话？" → 向量搜原文片段
```

**核心变化**：不是"AI 替你读完一本小说"，而是"AI 帮你聚合人类已有的解读"。前者是技术无法达到的，后者是 RAG 最擅长的。

## 技术方案

| 层 | 内容 | 和之前五层架构比 |
|----|------|----------------|
| 书评 RAG | 豆瓣/知乎/百科 → Embedding → Chroma | 替代了"原文因果库"，数据量小、结构清晰 |
| 原文检索 | 小说原文 → 关键词+向量 → 搜片段 | 保留，但不推理 |
| Memory | Redis 持久化多轮对话 | 保留，支持追问 |
| Tool Calling | 调豆瓣 API 查评分/评论 | 新增，丰富数据源 |

## 难度评估

| 阶段 | 内容 | 复杂度 |
|------|------|:--:|
| 1 | 爬取书评/百科数据 | ⭐ |
| 2 | 书评数据 RAG（Embedding + 检索） | ⭐ |
| 3 | 原文片段关键词检索 | ⭐ |
| 4 | Memory 多轮对话 | ⭐⭐ |
| 5 | 前端 UI | ⭐⭐ |

## 关键认知

> 花了大量时间推演技术方案，最后发现走不通——这不叫失败，叫排雷。比一头扎进去写三个月才发现强一万倍。

> RAG 的真实边界非常窄：它能搜，不能理解。把 RAG 当搜索工具用，不要当大脑用。
