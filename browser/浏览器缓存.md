# 浏览器缓存机制

> 浏览器缓存存储与请求关联的响应，并将存储的响应复用于后续请求，加快客户端响应速度，减少服务器负载。

![浏览器缓存机制](browser-cache-frames/frame_01_title.png)

---

## 一、缓存查找流程

![缓存查找流程](browser-cache-frames/frame_02_flow.png)

```
浏览器发起请求
       ↓
  检查强缓存 ──────────────────────┐
       ↓ 未命中/过期               │ 命中且未过期
  进入协商缓存                      ↓
       ↓                    直接返回缓存资源
  发送请求到服务器                  (200 from cache)
  携带 If-Modified-Since
       或 If-None-Match
       ↓
  服务器验证资源 ─────────────────┐
       ↓ 已修改                   │ 未修改
  返回新资源                        ↓
  (200 + 新数据)              返回 304
                              使用本地缓存
```

## 二、强缓存 vs 协商缓存

![强缓存与协商缓存对比](browser-cache-frames/frame_03_compare.png)

### 强缓存

**特点**：直接从缓存读取资源，不发送请求到服务器，状态码 200，Size 显示 `from disk cache` 或 `from memory cache`。

#### Cache-Control（HTTP/1.1）

| 指令 | 含义 |
|------|------|
| `max-age=300` | 请求正确返回后的 300 秒内命中强缓存 |
| `no-cache` | 跳过强缓存，直接进入协商缓存验证 |
| `no-store` | 禁止浏览器缓存，每次都从服务器获取 |
| `public` | 可被所有用户缓存（包括代理服务器） |
| `private` | 仅浏览器可缓存，代理服务器不可缓存 |
| `must-revalidate` | 缓存过期后必须去服务器验证 |

> ⚠️ **注意**：`no-cache` ≠ 不缓存，而是跳过强缓存直接进入协商验证。

#### Expires（HTTP/1.0）

指定资源到期时间（绝对时间）。**缺点**：受限于本地时间，修改本地时间可能导致缓存失效。

**优先级**：`Cache-Control` > `Expires`

### 协商缓存

**特点**：强缓存失效后，浏览器携带缓存标识向服务器发起请求，由服务器决定是否使用缓存。

| 结果 | 状态码 | 说明 |
|------|--------|------|
| 命中 | 304 | 资源未修改，使用本地缓存 |
| 未命中 | 200 | 资源已修改，返回新资源 |

#### Last-Modified / If-Modified-Since

```
首次请求: 服务器返回 Last-Modified: Wed, 15 May 2024 08:00:00 GMT
再次请求: 浏览器发送 If-Modified-Since: Wed, 15 May 2024 08:00:00 GMT
服务器对比: 未修改 → 304 | 已修改 → 200 + 新资源
```

**缺点**：
- 精度仅秒级，1 秒内多次修改无法准确判断
- 文件未改但打开/保存也会更新 Last-Modified

#### ETag / If-None-Match

```
首次请求: 服务器返回 ETag: "abc123"
再次请求: 浏览器发送 If-None-Match: "abc123"
服务器对比: ETag 相同 → 304 | 不同 → 200 + 新资源
```

**优点**：基于资源内容生成唯一标识，精度更高
**缺点**：计算成本较大，服务器集群场景可能不一致

**优先级**：`ETag` > `Last-Modified`

## 三、缓存存储位置

![缓存存储位置](browser-cache-frames/frame_04_storage.png)

浏览器按以下优先级查找缓存：

```
┌─────────────────────────────────────────────────────────┐
│  1. Service Worker    独立线程，可编程控制缓存策略        │
│  2. Memory Cache      内存缓存，读取快，容量有限          │
│  3. Disk Cache        硬盘缓存，容量大，根据 HTTP Header  │
│  4. Push Cache        HTTP/2 推送缓存，连接关闭即释放     │
└─────────────────────────────────────────────────────────┘
        优先级从高到低 ▼
```

### Memory Cache vs Disk Cache

| 条件 | 存储位置 |
|------|----------|
| 小文件 | 优先内存 |
| 大文件 | 优先硬盘 |
| 内存使用率高 | 优先硬盘 |

## 四、用户行为对缓存的影响

![用户行为对缓存的影响](browser-cache-frames/frame_05_user.png)

### 不同操作方式的缓存行为

| 操作 | 快捷键 | 缓存行为 |
|------|--------|----------|
| 地址栏输入 | - | 查找 disk cache，命中则使用 |
| 普通刷新 | F5 | 优先 memory cache → disk cache → 请求服务器 |
| 强制刷新 | Ctrl+F5 | 跳过所有缓存，直接请求服务器 |

### 其他用户行为

| 操作 | 缓存行为 | 说明 |
|------|----------|------|
| 前进/后退按钮 | 使用缓存 | 不会重新请求，直接从缓存读取 |
| 点击链接 | 查找 disk cache | 与地址栏输入行为一致 |
| 预加载资源 | 存入 memory cache | `<link rel="prefetch">` 下载的资源优先存入内存 |
| Service Worker 拦截 | 自定义策略 | 可编程控制，优先级最高 |

> 💡 **提示**：普通刷新时 memory cache 可用是因为 TAB 未关闭；强制刷新会发送 `Cache-Control: no-cache` 和 `Pragma: no-cache` 请求头。

## 五、缓存策略：按文件类型配置

![缓存策略配置](browser-cache-frames/frame_06_strategy.png)

| 文件类型 | 策略 | 配置示例 | 说明 |
|----------|------|----------|------|
| HTML | 协商缓存 | `Cache-Control: no-cache` | 保证改变能及时更新 |
| 图片 | 短期强缓存 | `Cache-Control: max-age=86400` | 1 天过期，替换为主 |
| CSS | 长缓存 + 指纹 | `filename.[hash].css` | 文件名哈希，修改即更新 |
| JS | 长缓存 + 指纹 | `Cache-Control: private, max-age=31536000` | 含隐私信息时添加 private |

## 六、CDN 缓存

![CDN 缓存工作原理](browser-cache-frames/frame_07_cdn.png)

### 缓存命中流程

```
用户请求 → DNS 解析 → CDN 负载均衡 → 就近边缘节点
                                    ↓
                              有缓存 → 直接返回 (200 OK)
```

### 缓存未命中流程（回源）

```
CDN 未命中 → 向源站服务器请求 → 缓存资源 → 返回用户
                                    ↓
                              后续请求将命中缓存
```

### CDN 优化方向

| 策略 | 说明 |
|------|------|
| 静态资源边缘化 | 将静态资源部署到边缘节点 |
| 域名分片 | 突破同域名 6 并发限制 |
| 多级缓存 | 边缘 → 区域 → 中心 → 源站 |

## 七、总结

![总结](browser-cache-frames/frame_08_summary.png)

```
┌─────────────────────────────────────────────────────────┐
│                    浏览器缓存机制                        │
├─────────────────────────────────────────────────────────┤
│  强缓存优先 → 协商缓存验证 → 服务器返回                   │
│                                                         │
│  200 from cache  │  强缓存命中，不发送请求               │
│  304             │  协商缓存命中，资源未修改              │
│  200             │  缓存失效，返回新资源                  │
├─────────────────────────────────────────────────────────┤
│  缓存位置: Service Worker > Memory > Disk > Push        │
│  缓存策略: 按文件类型配置，兼顾更新与性能                 │
└─────────────────────────────────────────────────────────┘
```

**核心原则**：缓存 = 速度 + 效率
