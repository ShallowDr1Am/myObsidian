**Monorepo 改造**

> 主导 13 个独立前端仓库收敛为 pnpm workspace + turborepo 单仓（14 packages / 1841 源文件 / 31.6 万行 TS），以 `git subtree` 保留 4153 个历史提交（最早至 2022-06），迁移可追溯、可回滚 抽出 `pkg-local-config`（3 个文件）统一 11 个子应用的构建配置入口，配合 Module Federation `shared` + `externals` 消除公共库重复打包，**代码总计减少1w+行，平台加载 P90 由 1592ms 降至 929ms（-41.6%）**。

加载时间的来源：公司前端监控 Omega 的 `pageLoadTime`，口径是 navigationStart 到 load 事件，取的是线上真实用户的 P90
埋点的原理："浏览器会持续把各阶段时间戳记录在 `performance` 对象里，SDK 不需要自己测量，只是在合适的时机去读取并相减。它监听 `window load` 主要是为了冲刷队列——因为埋点事件可能比 load 更早产生，SDK 会先暂存，等 load 之后统一上报。而承载页面加载耗时的那个性能事件，实际是在 `visibilitychange` 变 hidden 时触发的，也就是用户离开页面那一刻，这样能保证数据完整。计算口径是 `loadEventStart - navigationStart`。"

**跨包类型产物门禁**

> 公共层 star-commons 以 `--emitDeclarationOnly` 只产出类型声明（94 个 `.d.ts`），通过 turbo `build.dependsOn` 串为 11 个子应用构建的前置产物：子应用改代码即时获得公共层类型提示，无需重复编译整个公共库，同时让类型错误在构建阶段即被拦截。

**CDN 双活容灾**

> 设计并落地前端 CDN 故障容灾：运行期探测 CDN 连通性（3s 超时），失败即写入降级标记并热切换至同源产物，用户侧仅感知一次刷新。构建期额外产出同源版 HTML，**20 处 CDN 引用全量改写为本机路径**，import map 覆盖 react/react-dom/antd/single-spa/lodash/moment/axios，**17 个兜底文件逐一核对完备**，避免降级后二次白屏。上线后单次真实 CDN 故障捕获 22 个独立客户端的降级记录。

**模块联邦聚合工单**

> 基于 Module Federation 实现跨业务域工单聚合：抽象 `loader.withRemoteComponent(subApp, exposeName)` 统一加载入口，运行期从注册表解析目标应用地址；公共层对业务子应用**零反向依赖**，故新增业务域无需改动宿主代码（依赖倒置）。工单详情页按业务类型装配 37 个远程组件、覆盖 4 个业务域；全仓 49 处联邦调用点，聚合 6 个业务域。react/react-dom 以 `singleton + eager` 共享，避免多实例导致 hooks 失效。
